### Detailed Explanation of Renaming Columns

1. **Purpose**:
   - Renaming columns in PySpark changes the name of one or more columns in a DataFrame, improving readability, standardizing names, or preparing data for downstream tasks.
   - Common scenarios:
     - Simplify long names (e.g., `Annual Salary` to `salary`).
     - Align names with conventions (e.g., `department` to `dept`).
     - Rename after transformations (e.g., cleaning or aggregations).

2. **Methods**:
   - **`withColumnRenamed(old_name, new_name)`**:
     - **Purpose**: Renames a single column from `old_name` to `new_name`.
     - **Syntax**:
       ```python
       df.withColumnRenamed("old_column", "new_column")
       ```
     - **Key Features**:
       - Simple and direct; modifies one column at a time.
       - Chain multiple calls to rename multiple columns.
       - Preserves all other columns and their order.
       - Returns a new DataFrame with the updated column name.
     - **Use Case**: Rename `Annual Salary` to `salary`.
     - **Example**:
       ```python
       df_new.withColumnRenamed("Annual Salary", "salary").show()
       ```

   - **`select()` with `alias()`**:
     - **Purpose**: Renames columns by selecting them with `col().alias()` or expressions, often used to rename multiple columns or combine with transformations.
     - **Syntax**:
       ```python
       df.select(col("old_column").alias("new_column"), col("other_column"), ...)
       ```
     - **Key Features**:
       - Flexible; allows renaming multiple columns in one operation.
       - Requires explicitly selecting all desired columns.
       - Can combine with expressions (e.g., `col("Annual Salary") * 0.1.alias("bonus")`).
       - Useful when transforming and renaming simultaneously.
     - **Use Case**: Rename `Annual Salary` to `salary` and `department` to `dept`.
     - **Example**:
       ```python
       df_new.select(col("Annual Salary").alias("salary"), col("emp_id")).show()
       ```

   - **SQL with `AS`**:
     - **Purpose**: Renames columns using SQL `SELECT` with the `AS` keyword, equivalent to `select()` with `alias()`.
     - **Syntax**:
       ```sql
       SELECT old_column AS new_column, other_column FROM table
       ```
     - **Key Features**:
       - Ideal for SQL-based workflows or `%sql` cells in Databricks.
       - Requires registering the DataFrame as a temporary view.
       - Supports renaming multiple columns and combining with other SQL operations.
       - Columns with spaces (e.g., `Annual Salary`) need backticks in SQL.
     - **Use Case**: Rename `Annual Salary` to `salary` in a SQL query.
     - **Example**:
       ```python
       df_new.createOrReplaceTempView("emp_table")
       spark.sql("SELECT Annual Salary AS salary, emp_id FROM emp_table").show()
       ```

3. **Key Features**:
   - **Preservation**: Renaming only changes column names, not data or types.
   - **Lazy Evaluation**: Operations are planned but executed only with actions (e.g., `display()`, `show()`).
   - **Column Names with Spaces**: Supported in PySpark (e.g., `Annual Salary`), but use backticks in SQL (`` `Annual Salary` ``).
   - **Uniqueness**: Ensure new column names are unique to avoid errors.
   - **Databricks Integration**: Use `display()` to verify renamed columns interactively.

4. **Use Cases with `df_new`**:
   - Simplify `Annual Salary` to `salary` for easier queries.
   - Rename `department` to `dept` for consistency.
   - Rename columns after cleaning (e.g., `salary` to `Annual Salary` after removing `$` and `,`).
   - Prepare data for reporting or visualization with clear column names.

### Handling Variations
- **Columns with Spaces**: Columns like `Annual Salary` are supported, but use backticks in SQL:
  ```sql
  SELECT `Annual Salary` AS salary FROM emp_table
  ```
- **Non-existent Columns**: `withColumnRenamed` ignores non-existent columns without error:
  ```python
  df_new.withColumnRenamed("non_existent", "new_name").show()  # No error, no change
  ```
- **Duplicate Names**: Ensure new names don’t conflict with existing columns:
  ```python
  # Wrong: df_new.withColumnRenamed("Annual Salary", "name") # Error if 'name' exists
  ```
- **Integration with Cleaning**: Rename after cleaning `Annual Salary`:
  ```python
  df_new = emp.withColumn("salary", regexp_replace(col("salary"), "[\\$,]", "").cast("double")) \
              .withColumnRenamed("salary", "Annual Salary")
  ```
- **Integration with Aggregation**: Rename before aggregating:
  ```python
  df_new.withColumnRenamed("Annual Salary", "salary") \
        .groupBy("department").agg(sum("salary").alias("total_salary")).show()
  ```

### Choosing the Right Method
- **Use `withColumnRenamed`**:
  - For simple, single-column renaming.
  - When you want to keep all columns without explicitly selecting them.
  - Example: `df_new.withColumnRenamed("Annual Salary", "salary")`.
- **Use `select` with `alias`**:
  - For renaming multiple columns in one operation.
  - When combining renaming with selecting specific columns or transformations.
  - Example: `df_new.select(col("Annual Salary").alias("salary"), col("emp_id"))`.
- **Use SQL**:
  - For SQL-based workflows or `%sql` cells in Databricks.
  - When combining renaming with other SQL operations.
  - Example: `SELECT Annual Salary AS salary FROM emp_table`.
